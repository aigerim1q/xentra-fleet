# Xentra Fleet

Агенты, которые ведут задачи Xentra от тикета в Jira до merge request в GitLab. Управление —
из Telegram, работа — на Mac владельца, по подпискам Claude и ChatGPT (без API-ключей).

Два режима, которые работают вместе:

- **Конвейер** — бот берёт тикет из Jira, предлагает план и критерии приёмки, после
  подтверждения ведёт одну задачу сам: приёмочный тест → разработка до зелёных гейтов →
  ревью двумя моделями (Claude и Codex) → MR → тикет в «Review».
- **Флот ролей** — `pm`, разработчики, аудиторы и тестировщик переписываются письмами,
  каждый в своей роли и со своими правами; владелец — один из адресатов, в Telegram.

Граница автономии одна для обоих: **push, MR, мерж, миграции БД и закрытие тикета — только
человек.** Агент может подготовить всё до этой точки и попросить; решает владелец кнопкой.

## Как устроено

```
Telegram ──► бот (node dist/cli.js bot)
               ├─ конвейер: Jira → план → [подтверждение] → разработка → ревью → MR
               └─ мост почты: письма флота ↔ чат владельца

Супервизор флота (node dist/cli.js fleet run)
   ~/.xentra-fleet/mail          почта ролей (Inbox / Sent / Archive / Acks)
   ~/.xentra-fleet/worktrees     рабочая копия на тред, ветка fleet/<тред>
   ~/.xentra-fleet/state         сессии тредов, память, лимиты, журналы, метрики
        │
        ├─ pm ──► xentra/dev (dev-1 | dev-2) ──► auditor + auditor-codex + tester ──► pm ──► владелец
        └─ наблюдатели: ci-watch (пайплайн MR), jira-watch (статус и комментарии)
```

Агенты запускаются как `claude -p` (или `codex exec` для Codex-ролей) в рабочей копии задачи.
У них **нет shell**: git, тесты, письма и push выполняет сам бот/супервизор по их запросу.

## Быстрый старт

Нужно:

- macOS, Node.js ≥ 20, git;
- Claude Code с входом по подписке (`claude`, затем `/login`);
- Codex CLI с входом через ChatGPT (`codex login`) — для второго ревьюера и `auditor-codex`;
- клоны рабочих репозиториев только для флота, например `~/WebstormProjects/fleet/back-ai` и
  `~/WebstormProjects/fleet/front-ai` (не те, в которых работаешь руками), с `node_modules`;
- Telegram-бот от @BotFather, токены Jira (PAT) и GitLab.

```bash
npm install
cp .env.example .env      # заполнить: Jira, GitLab, пути к клонам, Telegram
npm run build

node dist/cli.js bot        # Telegram: конвейер + мост почты флота
node dist/cli.js fleet run  # супервизор флота ролей (отдельный процесс)
```

**Не кладите `ANTHROPIC_API_KEY` / `OPENAI_API_KEY` в `.env`:** окружение передаётся агентам, и
`claude` может списывать сессии с API-счёта вместо подписки. Токены Jira, GitLab и Telegram
бот из окружения агентов вычищает сам.

Бот и супервизор живут, пока открыт ноутбук и запущены процессы.

## Telegram

Меню из четырёх кнопок:

| Кнопка | Что делает |
|---|---|
| **📋 Задачи** | твои задачи из Jira; в карточке — кому отдать: **🤖 Бот** (сам доведёт до MR, быстро) или **👥 Команда** (Зам. CTO, разработчик, два аудитора, тестировщик); смена статуса |
| **🛰 Что происходит** | бот и команда одним экраном: кто над чем работает, что ждёт твоего решения, расход; кнопки «Сессии» (что делал агент + как открыть сессию в терминале) и «Метрики» |
| **🧑‍💼 Зам. CTO** | просто пиши в чат, как человеку: пока команда запущена, отвечает `pm` в постоянном разговоре — помнит прошлые разговоры, видит всю команду, может поставить задачу |
| **⚙️ Управление** | пауза команды, снять дневные лимиты, остановленные треды, прервать работу бота, не брать новые тикеты — всё кнопками |

Решения приходят сами, с кнопками: «Подтвердить» план, ответы на вопросы агента, «🚀 Push и MR» / «✋ Не сейчас», «🔀 Смержить». На письмо команды можно ответить реплаем — ответ уйдёт в эту задачу. Если команда не запущена, свободный текст понимает сам бот («что происходит», «сколько потратили»).

Команды для тех, кто привык: `/start`, `/help`, `/tasks`, `/status`, `/sessions`, `/fleet <задача>`, `/kill`, `/veto <тред>`.

## Роли флота

| Адрес | Модель | Права | Задача |
|---|---|---|---|
| `xentra/pm` | Opus 5.5 | чтение | разбирает задачу, раздаёт работу, собирает итог, просит push |
| `xentra/dev` → `dev-1`, `dev-2` | Sonnet 5.5 | правка файлов | реализует задачу в рабочей копии треда, заказывает гейты |
| `xentra/auditor` | Opus 5.5 | чтение | ревью: архитектура, безопасность, граничные случаи |
| `xentra/auditor-codex` | gpt-6-astra, high | чтение | то же, независимо, на другом провайдере |
| `xentra/tester` | Sonnet 5.5 | чтение | критерии приёмки, гейты, сценарий ручной проверки |
| `xentra/owner` | — | — | владелец, в Telegram |

Роли — `roles/<роль>.json` (модель, права, тайм-аут, кто может писать) и `roles/<роль>.md`
(инструкции); общий протокол — `roles/_protocol.md`. Подробно о флоте: [`docs/FLEET.md`](docs/FLEET.md).

## Безопасность

- Агенты без shell и без MCP; правка CI, lock-файлов, `.env`, миграций и конфигов гейтов
  запрещена механически (`src/engine/guardrails.ts`); режим `--restricted`.
- Ослабить проверку нельзя тихо: удаление тестов, skip-маркеры и правки конфигов гейтов
  ловятся без LLM (`gateIntegrity.ts`); при противоречии тестов и задачи агент обязан
  остановиться и спросить.
- Секреты не попадают ни к агентам, ни в тексты: токены вычищаются из окружения, ответы,
  журналы, письма и память проходят маскирование.
- Telegram отвечает только разрешённым chat id / user id; дашборд — только на 127.0.0.1,
  POST — с токеном.
- Защита от зацикливания: > 30 писем в треде за 30 минут (или > 10 коротких) — тред
  останавливается, владельцу уходит уведомление.

## Контекст и время

Как у флота CTO: одна сессия на задачу/тред, продолжается через `--resume`; переполнение
окна сжимает сам Claude Code. Ход ограничен временем, а не токенами: 30 минут без вывода или
5 часов на ход — остановка, незаконченные правки сохраняются коммитом `wip: checkpoint`,
задача уходит владельцу с кнопкой «Продолжить (та же сессия)». Каждый ход пишется в журнал
`.jsonl` (секреты замаскированы).

Перед стартом PM и разработчик получают справку без участия модели: карточку Jira,
последние комментарии, MR задачи и статус пайплайна.

## Консоль CTO в терминале

```bash
node dist/cli.js cto          # твоя постоянная сессия Claude Code для управления флотом
node dist/cli.js cto --new    # начать новый разговор вместо продолжения
```

Папка `~/.xentra-fleet/cto`: её `CLAUDE.md` объясняет сессии флот и команды, чтобы смотреть
статус, треды, сессии и метрики (они разрешены без вопросов) и ставить задачи от твоего имени
(письмо — только когда попросишь, с подтверждением). Каждый запуск продолжает тот же разговор.
Внизу строка: `[модель · контекст · расход] команда: ▶ сколько работают · ✉️ писем тебе`.
Это не «Зам. CTO» из Telegram — там отвечает `pm` внутри команды.

## Смотреть за агентами

```bash
node dist/cli.js watch -f                  # все агенты вживую: что читают, правят, пишут
node dist/cli.js watch -f --task XEN-55    # одна задача (или fleet-<тред> для флота)
node dist/cli.js watch --role dev-1        # последние сессии одной роли
node dist/cli.js watch --list              # сессии с командой, чтобы открыть их в Claude Code
node dist/cli.js open                      # выбрать сессию по номеру и сразу открыть её в Claude Code
```

```
[XEN-55 dev] ▶ сессия 099500e0 · claude-sonnet-5-5
[XEN-55 dev] → Поиск по коду: "archived"
[XEN-55 dev] → Правка src/modules/documents/documents.service.ts
[XEN-55 dev] 💬 Фильтр не учитывал архивные записи, добавил условие…
[XEN-55 dev] ■ готово · ~$0.42 · 184 с · 23 ходов
```

Открыть сессию агента целиком в Claude Code — командой из `watch --list`:
`cd <папка> && claude --resume <id> --fork-session`. `--fork-session` обязателен: без него
твои сообщения попадут в сессию, которую агент продолжит, и собьют ему контекст.

Сырые журналы (`.jsonl`, секреты замаскированы): `.harness-state/tasks/<KEY>/sessions/` для
конвейера, `~/.xentra-fleet/state/tasks/fleet-<тред>/sessions/` для флота. Состояние флота —
`node dist/cli.js fleet mail thread <тред>` и `/fleet_status` в Telegram.

## Настройка

Все параметры — в `.env.example`, с комментариями. Главное:

| Группа | Переменные |
|---|---|
| Jira, GitLab | `JIRA_BASE_URL`, `JIRA_PAT`, `GITLAB_BASE_URL`, `GITLAB_TOKEN`, `GITLAB_TARGET_BRANCH` |
| Репозитории и гейты | `BACKEND_REPO_PATH`, `BACKEND_VERIFY_CMD`, `BACKEND_GATE_TYPECHECK`, … (то же для `FRONTEND_`) |
| Telegram | `TELEGRAM_BOT_TOKEN`, `TELEGRAM_ALLOWED_CHAT_IDS`, `TELEGRAM_ALLOWED_USER_IDS` |
| Модели конвейера | `PROPOSE_MODEL`, `IMPLEMENT_MODEL`, `REVIEW_MODEL`, `CODEX_REVIEW_MODEL`, `CODEX_REVIEW_EFFORT`, … |
| Время и контекст | `AGENT_IDLE_TIMEOUT_MS`, `AGENT_TURN_TIMEOUT_MS`, `SESSION_LOG_RETENTION_DAYS` |
| Лимиты конвейера | `MAX_ITERATIONS`, `MAX_BUDGET_USD`, `DAILY_BUDGET_USD`, `MAX_TASKS_PER_DAY` |
| Флот | `FLEET_CLAUDE_DAILY_USD`, `FLEET_CLAUDE_DAILY_SESSIONS`, `FLEET_CODEX_DAILY_SESSIONS`, `FLEET_MERGE_BOT` (`off` / `notify` / `auto`) |

Модели ролей флота — в `roles/*.json`.

## Командная строка

```bash
node dist/cli.js bot                      # Telegram
node dist/cli.js fleet run | once         # супервизор: постоянно | обработать всё и выйти
node dist/cli.js fleet mail send --to xentra/pm --subject "XEN-55" --body "…" --key XEN-55
node dist/cli.js fleet mail check | read <id> | thread <id>
node dist/cli.js fleet roles | metrics --days 7 | hold list | hold release <тред>
node dist/cli.js run --repo <путь> --task "<текст>" --verify "yarn test"   # разовая задача без Jira
node dist/cli.js eval --k 3               # прогон eval-набора: pass@1 и pass^k
node dist/cli.js eval-harvest --dry-run   # собрать кейсы из закрытых тикетов
node dist/cli.js dashboard                # локальный дашборд
```

## Eval

`evals/cases/` — реальные закрытые задачи XEN: текст тикета как задача, коммит до MR как
база, тесты из MR как скрытый гейт. Нужен для сравнения моделей и промптов до и после
изменений: `eval --k 3 --model <модель>`. Новые кейсы собирает `eval-harvest` (пропускает
MR без тестов, MR на несколько тикетов и MR размером с фичу).
